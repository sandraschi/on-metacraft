# Contributing - on-metacraft

## System of record

GitHub Issues (like the sister repos).

## Rule 1 - Observability (per claim)

Every cost-collapse claim resolves to a dateable, checkable public fact:
first commit / release with date, commit-author counts, court ruling with
docket and date, published price list, datasheet, financial filing, dated
press statement. Quoted public speech for intentions. Private pipelines do
not exist for this book until publicly evidenced.

## Rule 2 - Hazard (HARD, non-negotiable)

In scope: institutional facts, governance criteria, control failures with
dates. Out of scope, always cut on sight: exploit / EDR-evasion technique,
weapons guidance or targeting detail, illicit procurement or logistics
how-tos, controlled-substance precursors, code or configuration that defeats
a named protection. Weapons domain defers to `on-hyperwar`.

Test: does this paragraph help a principal attach a brake, or help an
operator press an accelerator? Ship only the first.

## Rule 3 - Legal hygiene

Name real projects only in their own terms. "Clean-room" means what the
project says it means; never "laundering". No claim that a named product
infringes or does not infringe; describe the doctrine and cite the case.
This book is not legal advice and says so in the preface.

## Prose

Beats first (3-5 facts per section), ugly draft, 3 AI variants constrained
to the README voice, red-team for flab, read aloud (declaim), lore-keep
dates. ASCII prose (no em dashes, no smart quotes). No single-pass AI
chapters.

Technical precision (hard gate): not "the app" - the document model, the
command registry, the compositor oracle, the tile cache. Not "the law" -
s.102(b), s.1201(f), Art. 6 Software Directive, the specific ruling.

## Definitions

- `[construction]` = asserted, not yet evidenced. Required flag, never silent.
- No evidence-by-proximity: a roadmap is not a shipped app.
- Fleet link: each chapter closes with one paragraph tying its step to the
  parallel step in a sister book.
